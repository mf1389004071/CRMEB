# 菜集鲜独立仓库与区域匹配方案

> 定稿依据：`.cursor/plans/独立仓库区域匹配_46eb4a4d.plan.md`；客户简版需求见同目录 `261029-客户需求.md`。

## 1. 背景与结论

客户简版四点：注册、切城差异价、网站下单次日指定仓提货现金付、后台打印。

| 客户点 | 改造前 | 结论 |
|--------|--------|------|
| 注册 | VN 登录裁剪已有 | 基本匹配 |
| 切城差异价 | 配送区域 + 区域价 | 价匹配；无仓实体 |
| 次日指定仓提货 | 到付 COD；无仓 | 半匹配 → **本方案补齐** |
| 提货打印 | 到付打印已有 | 打印加仓信息 |

库内原先**无独立仓库**。官方 `eb_system_store` 是门店自提核销点，实现方案明确不用门店价冒充区域价。订单只记 `region_id`。

**已拍板：**

1. 下单自动匹配默认仓，用户可在同匹配集内改选。
2. 价格继续按区划区域价；仓只管提货/快照/打印。
3. 到付列表按仓筛（可与销售区并用）。
4. 配送区域页可快捷设默认仓；已有则二次确认覆盖。
5. 管理端减负：快速开仓、高级选项折叠、隐藏官方提货点菜单、缺仓健康提示。

方案 A（一城一仓约定）无法覆盖一城多仓与精确/模糊匹配，本方案采用独立仓。

## 2. 模型

- **销售区**：`Cb-region` → 区域价/可售（不变）。
- **提货仓**：地址 `city_id` 祖先链最细→最粗匹配 → 默认仓可改 → 订单快照。
- 不复用 `eb_system_store`。

### 2.1 切城颗粒度与下单校验

| 用途 | 粒度 | 说明 |
|------|------|------|
| H5 顶栏切城 / 热门 | **城 level0 + 区/郡 level1**（`SWITCH_MAX_LEVEL=1`） | 不下发坊；一城一仓开城即可，区分价/分仓再开放对应区 |
| 收货地址 | 可到坊 level2+ | `address_children` 全层级 |
| 提货仓匹配 | 按地址链细→粗 | 与切城头独立；`exact_match_only` 才锁死坊 |

下单地址与销售区：`addressInRegion` **或** 双方 level0 祖先相同（同城兄弟坊可下单；跨城拒绝）。订单详情/到付/打印展示 `warehouse_*` 快照。

## 3. 表结构

- `eb_vn_warehouse`：主数据（启用、生效窗、提货时段 JSON、`auto_match`、`exact_match_only`、排序等）。
- `eb_vn_warehouse_region`：仓 ↔ 任意颗粒度 `city_id`（`sort`、`is_default`）。
- `eb_store_order`：`warehouse_id` / `warehouse_name` / `warehouse_address` 快照。
- 多语：`eb_i18n_content`，`entity_type=warehouse`。

迁移：`crmeb/database/vn/031_warehouse.sql`、`032_warehouse_menu.sql`；演示：`demo/002_warehouse_demo.sql`。

## 4. 匹配算法

1. 仓过滤：启用、生效窗内、`auto_match=1`、未删。
2. 关联 `city_id IN chain(地址)`。
3. `exact_match_only=1` 时仅关联节点等于地址最细节点。
4. 取获胜粒度（chain 索引最小的关联层）。
5. 匹配集排序：`is_default DESC` → 关联 `sort DESC` → 仓 `sort DESC` → `id`。
6. 默认=第一条；无候选则下单拦截。

## 5. 管理端 / H5

- 设置 → 提货仓库：CRUD、快速开仓、高级折叠、区划关联、多语。
- 配送区域：设默认提货仓 + 覆盖确认 + 默认仓列展示。
- 到付：仓筛、本仓快捷、打印带仓。
- H5 确认单：展示/切换匹配仓；提交 `warehouse_id`。
