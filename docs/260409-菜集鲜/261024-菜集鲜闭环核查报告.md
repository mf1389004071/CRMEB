## 0. 先答：为什么 `/admin/setting/freight/city/list` 不能从国家级开始选？

### 0.1 你打开的是官方旧页，不是菜集鲜区划页

| 对比项 | 官方「城市数据」（你打开的页） | 菜集鲜「配送区域」（自定义功能） |
|--------|-------------------------------|----------------------------------|
| URL | `http://localhost:8089/admin/setting/freight/city/list` | `http://localhost:8089/admin/setting/region` |
| 菜单 | 设置 → 运费相关 → **城市数据**（`setting-system-city`，`is_show=1`） | 设置 → **配送区域**（`admin-setting-region`，`is_show=1`） |
| 前端 | `template/admin/src/pages/setting/cityDada/index.vue` | `template/admin/src/pages/setting/region/index.vue` |
| 后端 | `SystemCity` / `SystemCityServices` | `adminapi/region/*` / `RegionAdminServices` |
| 首层 | `parent_id=0` → **中国各省**；根文案写死「中国」 | `level=-1` → **国家根（中国 / Việt Nam）**，面包屑「国家」 |
| 能力 | 省市区增删改、清缓存；**无** `is_open` / `is_hot` / `path` / 导入重建 | 开放白名单、热门、排序、Excel 导入、重建 path、跳多语 |

### 0.2 根因（设计刻意，不是漏做）

1. **国家根不挂在 `parent_id=0` 下**  
   迁移 `crmeb/database/vn/020_region.sql`：国家节点 `level=-1`、`parent_id=-1`，`city_id` 为 `900001`(CN)、`900002`(VN)。  
   目的：避免旧运费模板 / 官方城市选择器被国家根打断；**不改 CN 存量省节点的 `parent_id=0`**。

2. **官方服务写死中国根**  
   `SystemCityServices::getSonCityList`：`parent_id=0` 时 `parent_name='中国'`，只列省级；`createCityForm` 无父时同样写死「中国」。  
   该页**从未接入**国家根查询（`level=-1`）。

3. **菜集鲜管理端已支持国家级**  
   `RegionAdminServices::lst`：`parent_id<=0` 时 `where level=-1`；进入 CN 后再特殊列出 `level=0 AND country_code=CN`（因 CN 省仍 `parent_id=0`）。  
   页面面包屑第一级即「国家」。

### 0.3 本地库实测（2026-10-24）

| city_id | name | level | parent_id | country_code | is_open |
|---------|------|-------|-----------|--------------|---------|
| 900001 | 中国 | -1 | -1 | CN | 0 |
| 900002 | Việt Nam | -1 | -1 | VN | 1 |

VN 业务树：`level0=5` / `level1=12` / `level2=5`（**仅 `021_region_seed_vn.sql` 演示种子**，非完整行政区）。

### 0.4 正确用法

- **销售区 / 热门 / 区域价挂载 / 地址级联（VN）** → 只用 **设置 → 配送区域**（`/admin/setting/region`）。  
- **运费模板城市树（历史 CN）** → 可继续用官方「城市数据」，但**不要**在此维护 VN 销售区。  
- 两入口目前**并存且都显示**，易误用 → 见下文调整建议 P0-1。

## 7. 建议的最短验收路径（数据灌好后）

1. 管理端：配送区域 → 见「中国 / Việt Nam」→ 开放河内等 → 设热门 → 重建 path。  
2. 商品：区域价导入 → 生鲜属性 → 多语。
