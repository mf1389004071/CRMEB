## 0. 实现约束（必读，违反即返工）

### 0.1 技术栈与语法
| 项 | 约束 |
|----|------|
| PHP | **7.4**。禁用：`match`、命名参数、`?->`、构造器属性提升、联合类型、`str_contains` 等 PHP8 函数、`enum`、`readonly` |
| 框架 | ThinkPHP 6；分层 **Controller → Services → Dao → Model**；用 `app()->make(XxxServices::class)` 取服务；响应用 `app('json')->success()/fail()/status()` |
| 表前缀 | `eb_`（SQL 中直接写 `eb_`，与 `database/add_lang_vi_vn.sql` 一致） |
| 前端 | `template/uni-app`（Vue2 + vue-i18n，H5 编译）；`template/admin`（Vue2 + iView/Element，中文） |
| 金额 | PHP 用 `bcadd/bcmul` 等字符串运算，不用浮点直接加减 |

### 0.2 改动纪律
1. **禁止删除**既有代码/文件；停用功能用**配置开关**或**注释**（注释处写明 `// VN: 原因`）。
2. 新能力优先**新表、新类、新文件**；改核心文件只做**最小钩子**，并登记到 §5 的“核心文件改动清单”。
3. 新增后端类放对应目录并遵循现有命名：`app/model/...`、`app/dao/...`、`app/services/...`、`app/adminapi/controller/v1/...`、`app/api/controller/v1/...`；类头保持与现有文件一致的版权注释块。
4. **新增文案**（接口 `msg`、前端按钮）走现有多语言机制：接口 `msg` 写中文原文（`getLang()` 以中文为 key 翻译），并**同时在 `lang_code` 补 vi/en 词条**（见 M0-3）；前端用 `$t('key')`，key 同步入库。
5. 每个任务完成后：自测通过 → 更新 §11 勾选 → 单独提交（提交信息沿用仓库风格：`feat(模块): 简述`）。
6. 不确定之处：先读代码确认；仍不确定，在任务下记录**假设**并继续，不要停下来问。

### 0.3 数据库迁移约定
- 所有 DDL/初始数据放 `crmeb/database/vn/`，文件名 `NNN_说明.sql`（三位序号，**幂等**：`CREATE TABLE IF NOT EXISTS`；加列前用 `information_schema` 判断或写成可重复执行的存储过程/条件语句）。
- 同步提供回滚说明（注释即可）。
- **不要改** `public/install/crmeb.sql`（安装包基线）；全新安装需先装基线再执行 `database/vn/*.sql`，在 `database/vn/README.md` 写明顺序。
- 加列统一：`ALTER TABLE ... ADD COLUMN`，带 `COMMENT`，**默认值保证旧数据不受影响**。

## M0 基础

### M0-1 语言码规范化
**目标**：全链路统一为 `zh-CN`/`vi-VN`/`en-US`，兼容历史别名。
**后端**：
1. 在 `app/common.php` 新增 `normalize_lang_code(string $code): string`（`function_exists` 保护）。规则（先 `trim`，统一小写并把 `_` 换 `-` 比较）：
   - `vi`、`vi-vn` → `vi-VN`；`zh`、`zh-cn`、`zh-hans`、`zh-hans-cn` → `zh-CN`；`en`、`en-us`、`en-gb` → `en-US`；其余原样返回；空串返回空串。
2. 新增 `current_lang_code(): string`：读 `cb-lang` 头 → 规范化；无则 `sys_config('default_lang')`/默认语言（`lang_type.is_default`）→ 再无则 `vi-VN`。**把 `getLang()` 与 `getLangJson()` 里读取 `cb-lang` 的两处改为调用它**（注意 `getLang` 中“系统默认语言→Accept-Language→zh-CN”的兜底顺序改为 “默认语言 → vi-VN”，Accept-Language 不再参与，避免浏览器语言造成漂移）。
3. `config/lang.php` 别名保持，不改。
**数据**：`database/vn/001_lang_vi_vn.sql`：
   - 若无 `file_name='vi-VN'` 则插入 `lang_type`（`language_name='Tiếng Việt'`，`status=1`）；插入 `lang_country(code='vi-VN', type_id=新id)`（`vi_vn` 旧行保留，并**把旧行 `type_id` 也指向同一 type** 以兼容）。
   - 若存在旧 `vi_vn` 类型的 `lang_code`，复制到新 type（按 `code` 去重）；否则从 `type_id=1`（中文）复制作为待翻译占位（沿用 `add_lang_vi_vn.sql` 的写法）。
   - 设 `vi-VN` 为默认：`UPDATE eb_lang_type SET is_default = (file_name='vi-VN')`。
   - 仅启用三种语言：`UPDATE eb_lang_type SET status = file_name IN ('zh-CN','en-US','vi-VN')`（不删数据）。
   - 清缓存：迁移后手动执行 `php think` 对应清理或调用 `CacheService::delete` 上述缓存键；并递增 `lang_version`（找到版本号存放位置：`grep -rn "lang_version\|getLangVersion"`）。
**前端**：`utils/lang.js`、`App.vue`、`pages/users/user_info/index.vue`：写入/比较 `locale` 前先规范化；H5 默认 `vi-VN`（**不再取 `navigator.language`**）；语言选择只列三种。
**验收**：
- `curl -H "Cb-lang: vi_vn" .../api/get_lang_json` 与 `Cb-lang: vi-VN` 返回同一语言包；`Cb-lang: zh_cn` 返回中文；不带头默认越南语。
- 接口 `msg` 在 `Cb-lang: vi-VN` 下返回越南语（词条已存在时）。

### M0-2 migration 目录与 README

### M3-3 `app/services/order/CodOrderServices.php`
```php
class CodOrderServices extends BaseServices {
    const F_PENDING = 0;   // 待确认
    const F_STOCKUP = 1;   // 备货中
    const F_DELIVERING = 2;// 发货中
    const F_DELIVERED = 3; // 已送达

    // 到付单创建后钩子（pay offline 分支之后调用）
    public function onCreated(array $order): void;
    // 后台：确认接单 0→1
    public function confirm(int $oid, array $operator): bool;
    // 后台：开始配送 1→2（可选 delivery_uid/delivery_name/delivery_id=司机电话）
    public function startDelivery(int $oid, array $driver, array $operator): bool;
    // 送达核销：按 order_id + code 或按 code(+手机后四位)；2→3（也允许 1→3）
    public function verifyDelivered(string $orderIdOrCode, ?string $code, array $operator): array;
    // 后台：确认收款（扩展 OrderOfflineServices::orderOffline），记 received/collector/time
    public function collect(int $oid, string $received, string $remark, array $operator): bool;
    // 后台取消：fulfil<3 且未收款；回退库存、is_cancel=1
    public function adminCancel(int $oid, string $reason, array $operator): bool;
    // 用户取消守卫（供 cancelOrder 调用）：返回是否允许
    public function userCanCancel(array $order): bool;
    // 完结：fulfil=3 且 paid=1 → status=3
    protected function tryFinish(int $oid): void;
    // 生成不重复 6 位送达码
    protected function genDeliveryCode(): string;
}
```
**逻辑要点**
- `onCreated`：`is_cod=1`；`fulfil_status = sys_config('cod_auto_stock_up',1) ? 1 : 0`；`delivery_code=genDeliveryCode()`；`cod_receivable=pay_price`；`lang=current_lang_code()`；写 `region_id/currency` 快照；写审计 `cod_created`；若手机号/IP 在黑名单或超限 → **在 createOrder 之前拦截**（M9）。
- `confirm`：仅 `fulfil=0`；→1；审计。
- `startDelivery`：仅 `fulfil in (0,1)`；→2；`delivery_type='send'`，填 `delivery_name/delivery_id/delivery_uid`（复用现有配送员 `DeliveryServiceServices`）；**不修改 `status`**；审计。
- `verifyDelivered`：校验 `is_cod=1,is_cancel=0,fulfil in (1,2)`，`delivery_code` 相等；→3，`delivered_time`；审计 `cod_code_verify`；调用 `tryFinish`；返回订单摘要（供核销页展示：订单号、收货人、应收金额、是否已收款）。
- `collect`：沿用 `OrderOfflineServices::orderOffline`（**直接调用**，不重复写资金流水）；其前后补：`cod_received=$received`（默认 `pay_price`，若与应收不同需 `remark` 必填，并写 `cod_amount_edit` 审计）、`cod_collector_id`、`cod_collect_time`；然后 `tryFinish`。已收款再收返回错误。
- `tryFinish`：`is_cod && fulfil=3 && paid=1 && status=0` → `status=3`（直接完结，营销模块已关闭，无需走 `storeProductOrderUserTakeDelivery`；若发现该函数同时负责库存/销量回写则需调用——**实现前先读 `StoreOrderTakeServices::storeProductOrderUserTakeDelivery` 确认**）。
- `adminCancel`：**复用** `StoreOrderRefundServices::regressionStock($order)` 回退库存（`integralAndCouponBack` 一并调用无副作用）；设 `is_cancel=1`，`mark` 追加原因；已 `paid=1` 或 `fulfil=3` 时拒绝并提示“已收款/已送达订单请走售后”。
- `userCanCancel`：非 cod 单走旧逻辑；cod 单仅当 `fulfil=0 且 sys_config('cod_user_cancel_before_confirm',1)==1` 才 true。

### M2-2 `app/services/product/RegionPriceServices.php`（唯一取价入口）
```php
class RegionPriceServices extends BaseServices {
    public function enabled(): bool;                      // vn_mode_enable && region_pricing_enable
    public function currentRegionId(): int;               // current_region_id()
    public function chain(int $cityId): array;            // [自身, 父…国家] 按近→远；用 system_city.path 解析，缓存 10 分钟
    // 批量取价：返回 [ "{pid}_{unique}" => ['price','ot_price','stock','from_city_id'] ]，缺失的键=该规格在当前链上无价
    public function resolveSkus(array $pairs, int $cityId): array;
    // 列表用：给商品列表附加 price/ot_price（取可售规格的最小价），并按规则剔除不可售商品
    public function applyToList(array $list, int $cityId): array;
    // 详情/规格弹窗：返回规格数组上附加区域价；剔除不可售规格；全不可售 → 抛 ApiException('当前区域暂不销售该商品')
    public function applyToAttr(int $productId, array $attrValues, int $cityId): array;
    // 单规格取价（购物车/下单/realPrice）；无价返回 null
    public function resolveOne(int $productId, string $unique, int $cityId): ?array;
    // 是否允许回落全国价：system allow_national_price=1 且 product.allow_national_price=1
    public function nationalAllowed(int $productId): bool;
    // 商品 scope：给 StoreProductDao::search 追加“当前区域可售”条件
    public function visibleScope($query, int $cityId): void;
}
```
**取价规则（实现细节）**
1. `chain($cityId)` 返回从自身到国家根的 id 数组（索引 0 最近）。
2. `resolveSkus`：一次查询 `WHERE (product_id, unique) IN (...) AND city_id IN (chain) AND status=1`；对每个 `(pid,unique)` 取 `city_id` 在 `chain` 中**索引最小**的一条（最近祖先）。**不跨兄弟**——天然成立，因为只查链上节点。
3. 无命中 → 若 `nationalAllowed(pid)`：回落 `store_product_attr_value.price/ot_price/stock`；否则视为**不可售**。
4. `stock` 为 NULL 用规格表库存；非 NULL 用区域库存，扣减时同样走该字段（见 M2-4(5)）。
5. 所有价格计算结果以字符串/两位小数返回。
6. **未选区域（`cityId=0`）**：`enabled()` 为真时列表返回空 + `region_required=true`；详情/加购返回错误 `请先选择配送区域`；`enabled()` 为假时全部回落全国价（行为同原版）。
7. 缓存：`region_price:{pid}:{cityId}`，TTL 300s；价目增删改、导入后按 `product_id` 清缓存。

### M2-3 `visibleScope` SQL 形态
```sql
-- 商品在当前链上至少有一个有价规格，或允许全国价
(EXISTS (SELECT 1 FROM eb_store_product_region_price rp
         WHERE rp.product_id = eb_store_product.id AND rp.status = 1
```

## M6 币种

### M6-1 数据（`database/vn/060_currency.sql`）
`eb_system_currency(id, code varchar(8) UNIQUE, symbol varchar(8), name_zh, name_vi, name_en, decimal_places tinyint, thousand_sep varchar(2), decimal_sep varchar(2), rate decimal(18,6) COMMENT '1 本位币=rate 该币种', is_base tinyint, status tinyint, sort int, update_time int)`；预置 VND(is_base=1, rate=1, 0 位, `.` 千分位 `,` 小数位)、CNY(¥, 2 位)、USD($, 2 位)。
`eb_system_exchange_rate_log(id, code, old_rate, new_rate, operator_id, add_time)`。

### M6-2 `app/services/system/MoneyServices.php`
```php
class MoneyServices {
    public static function base(): string;                         // 'VND'
    public static function convert(string $baseAmount, string $code): string;       // bcmul 后按 decimal_places 四舍五入
    public static function format(string $amount, string $code, bool $withSymbol = true): string;
    public static function snapshot(string $baseTotal, ?string $code = null): array; // ['currency_code','exchange_rate','pay_amount_display']
    public static function resolveDisplayCode(): string;            // Cb-currency → user.display_currency → 区域国家默认(VN→VND,CN→CNY) → base
}
```
- 规则：区域价/订单/应付一律**本位币**；展示币只在**展示层**换算；**购物车合计与订单总价 = 本位币合计再换算**，行价仅展示（避免取整合计不一致）；展示币金额前缀 `≈`（本位币不加）。
- `createOrder` 后（M3 `onCreated` 内）写币种快照字段；汇率历史不回溯。

### M6-3 接口
`GET api/public/currency`（或并入公共配置）：币种列表、汇率、默认展示币种；`POST api/user/currency` 保存 `display_currency`。后台：`adminapi/setting/currency` CRUD；汇率修改写 `exchange_rate_log`；**不允许删除本位币，不允许同时两个本位币**。

### M6-4 前端
- 新增 `utils/money.js` `formatMoney(baseAmount)`（读取公共配置里的币种与汇率；本位币直接千分位；非本位币 `≈symbol` + 换算）。
- **先读 `components/BaseMoney.vue` 与全站金额展示点**（`grep -rn "BaseMoney\|toFixed\|¥\|￥" template/uni-app/pages template/uni-app/components`），所有价格/合计/运费/应付统一替换为 `BaseMoney`/`formatMoney`，**不得页面手写千分位或 ¥**。
- “我的/设置”里提供展示币种切换（三币种）。

### M6-5 验收

## 8. 常见陷阱（提前规避）

1. **`system_city.parent_id` 指向 `city_id`，不是 `id`**。写 SQL/Dao 别用错。
2. **`unique` 是 `store_product_attr_value.unique`（8 位字符串）**，与自增 `id` 不同；区域价、购物车、订单都以 `unique` 关联。
3. **订单金额一律 `bcmath`**；写库前统一两位小数。
4. **购物车 `productInfo` 是 JSON 快照还是读取时重组**：`handleCartList` 读取时从 `attrInfo` 取价，所以覆盖点在读取阶段；下单后 `cart_info` 才固化，别在下单后再改。
5. **未支付订单“线下付款，未支付”**：`tidyOrder` 里该分支条件 `!$order['status'] >= 2` 存在**运算符优先级 bug**（先取反再比较），不要依赖它；到付订单用 `is_cod` 分支优先处理。
6. **IP 获取**在反代后可能全是内网地址，M9 限频前必须核对。
7. **PHP 7.4 兼容**：每个任务提交前 `php -l` 检查新文件。
8. **前端缓存**：`localeJson`、`region` 存本地，换语言/换区域需清相应缓存，避免旧语言/旧区域价闪现。
9. **缓存键含语种/区域**，不要全站共用同一键。
10. **订单打印不含送达码**；送达码仅订单所有者可见。
11. **不要删除任何既有代码**；停用用开关/注释，并登记 §5。
12. **词条**：新 `msg` 若没有 vi/en 词条会回落成中文，验收时抽查三语。
