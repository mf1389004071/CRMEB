# 站点域名与静态资源切换说明

> 日期：2026-10-24  
> 场景：本地 Docker（`cjx-php:8089` + `cjx-mysql:33060`）访问时，页面静态图仍指向 `http://demo.crmeb.com/...`。  
> 用途：本地域名切换留档；后续换正式域名 / 宝塔上线时对照执行。

---

## 1. 问题原因

CRMEB 静态资源完整 URL 来自两处，缺一不可：

| 来源 | 位置 | 作用 |
|------|------|------|
| **站点域名配置** | 表 `eb_system_config`，`menu_name = site_url` | `set_file_url()` / 业务拼接相对路径时的前缀 |
| **业务数据里的绝对地址** | DIY、主题、商品图等字段 | 安装/导入 SQL 时常写死 `http://demo.crmeb.com`（含 JSON 转义 `http:\/\/demo.crmeb.com`） |

本地 Docker 安装后常见现象：

- `site_url` 为空或仍是演示站域名  
- `eb_diy` / `eb_theme` / `eb_store_product` 等仍含 `demo.crmeb.com`  
- 访问 `http://localhost:8089/` 时图片请求打到演示站（本机有文件也加载不到）

本地实测：`public/uploads/theme/...` 文件已在本机，只需把 URL 前缀切到本地域名即可。

---

## 2. 本地已做修复（Docker）

### 2.1 服务

```text
cjx-mysql  → 0.0.0.0:33060→3306
cjx-php    → 0.0.0.0:8089→8089（挂载 crmeb → /app，php -S router.php）
```

说明见 `crmeb/database/vn/README.md`「本地测试环境」。

### 2.2 数据库调整（核心）

将演示域名替换为本地：

```text
旧：http://demo.crmeb.com   （及 https、JSON 转义 http:\/\/demo.crmeb.com）
新：http://localhost:8089
```

必改项：

1. **`eb_system_config.site_url`** → `"http://localhost:8089"`（注意存的是带引号的 JSON 字符串）
2. **`eb_diy.value`**：DIY 装修 JSON 内图片 URL  
3. **`eb_theme`**：`home_*` / `category_*` / `detail_*` / `user_*` / `theme_*` 及对应 `*_default_*`  
4. **`eb_store_product`**：`image`、`slider_image`（`slider_image` 多为 JSON，需同时替换转义写法）

改完后清缓存：

```bash
# 容器内
rm -rf /app/runtime/cache/* /app/runtime/temp/*
```

或后台「清除缓存」。

### 2.3 前端源码（H5）

`template/uni-app/config/app.js` 本地 H5 使用同域：

```js
// #ifdef H5
HTTP_REQUEST_URL: window.location.protocol + "//" + window.location.host,
// #endif
```

- 已部署到 `crmeb/public/static` 的 H5：若构建产物未写死远程域名，改库后刷新即可。  
- **重新发行 H5** 后，同域配置才会打进新包。  
- 小程序 / APP 必须写死 API 域名，不能依赖 `window.location`。

管理端同域部署时 `VUE_APP_API_URL` 可留空（见 `docs/宝塔部署说明.md`）。

### 2.4 验证

```text
http://localhost:8089/uploads/theme/.../xxx.png  → 200
http://localhost:8089/                             → 200
http://localhost:8089/admin/                       → 200
```

库内不应再残留 `demo.crmeb.com`（至少查 `site_url`、diy、theme、store_product）。

## 3. 后续换成其他域名（通用步骤）

把下面的 `{OLD}` / `{NEW}` 换成实际值，例如：

| 环境 | 示例 |
|------|------|
| 本地 | `http://localhost:8089` |
| 测试 | `https://cjx-test.example.com` |
| 生产 | `https://cjx.alphavn.shop` |

### 3.1 必须改：数据库

```sql
-- 1) 站点配置（值一般是 JSON 字符串，带双引号）
UPDATE eb_system_config
SET value = '"{NEW}"'
WHERE menu_name = 'site_url';

-- 2) DIY（含 JSON 转义）
UPDATE eb_diy SET value = REPLACE(value, 'http:\\/\\/{OLD_HOST}', 'http:\\/\\/{NEW_HOST}') WHERE value LIKE '%{OLD_HOST}%';
UPDATE eb_diy SET value = REPLACE(value, 'https:\\/\\/{OLD_HOST}', 'https:\\/\\/{NEW_HOST}') WHERE value LIKE '%{OLD_HOST}%';
UPDATE eb_diy SET value = REPLACE(value, 'http://{OLD_HOST}', '{NEW}') WHERE value LIKE '%{OLD_HOST}%';
UPDATE eb_diy SET value = REPLACE(value, 'https://{OLD_HOST}', '{NEW}') WHERE value LIKE '%{OLD_HOST}%';

-- 3) 主题 / 商品等同理：普通 URL + JSON 转义各替换一遍
-- 表字段参考第 2.2 节
```

说明：

- `{OLD_HOST}` / `{NEW_HOST}` 只写主机（可带端口），如 `localhost:8089`、`demo.crmeb.com`。  
- `{NEW}` 写完整源，如 `https://your-domain.com`（协议与线上一致，建议 HTTPS）。  
- 若从本地迁到线上，`{OLD}` 常是 `http://localhost:8089`。  
- 若库仍是安装包演示数据，`{OLD}` 常是 `http://demo.crmeb.com`。

### 3.2 建议改：前端

| 端 | 文件/配置 | 线上怎么配 |
|----|-----------|------------|
| H5 同域部署 | `template/uni-app/config/app.js` | 用 `window.location...` 或发行前改为正式域名后重新编译 |
| 小程序/APP | 同上 `HTTP_REQUEST_URL` | **必须**改为正式 `https://域名` |
| 管理端 | `.env.production` → `VUE_APP_API_URL` | 同域可空；独立域名则填 API 根地址 |

### 3.3 改完必做

1. 清除 `runtime/cache`（或后台清缓存；有 Redis 时一并清配置缓存）  
2. 浏览器强刷；CDN/对象存储若开了，确认资源域名与 `site_url` 策略一致  
3. 抽查：首页装修图、商品主图、主题预览图是否都指向新域名

### 3.4 快速自检 SQL

```sql
SELECT menu_name, value FROM eb_system_config WHERE menu_name = 'site_url';
SELECT COUNT(*) FROM eb_diy WHERE value LIKE '%demo.crmeb.com%' OR value LIKE '%localhost:8089%';
SELECT id, home_image FROM eb_theme LIMIT 5;
SELECT id, image FROM eb_store_product WHERE image LIKE 'http%' LIMIT 10;
```

## 4. 宝塔线上部署：这些数据要不要改？

**要改。** 宝塔只解决「站点能跑」；**不自动**把库里的演示域名/`localhost` 换成你的正式域名。

### 4.1 全新安装（推荐）

用正式域名打开安装向导完成安装时，安装脚本会把 SQL 里的 `http://demo.crmeb.com` 替换成当前访问域名（见 `crmeb/public/install/index.php`）。

此时一般：

- `site_url` 已是正式域名  
- 基线 SQL 里演示站图片域名已被替换  

仍建议装完后执行第 3.4 节自检；若安装时用的是 IP 或临时域名，上线前再按第 3 节整体替换一次。

### 4.2 从本地库 / 备份库导入到宝塔（常见）

**必须调整**，否则线上页面会继续请求 `localhost:8089` 或 `demo.crmeb.com`。

操作顺序建议：

1. 宝塔配好站点域名、HTTPS、运行目录 `/public`（见 `docs/宝塔部署说明.md`）  
2. 导入数据库后执行第 3.1 节：  
   - `site_url` → `https://你的正式域名`  
   - 全库业务字段：`localhost:8089` / `demo.crmeb.com` → 正式域名（含 JSON 转义）  
3. 清 `runtime/cache`，必要时重启 PHP  
4. 前端：  
   - H5/admin 同域：可同域配置  
   - 小程序：改 `HTTP_REQUEST_URL` 后重新上传  
5. 后台「设置」里再确认站点域名与实际访问一致（改后台也会写 `site_url`，但**不会**批量改 DIY/主题/商品里已存的绝对 URL）

### 4.3 仅改域名、不重装

例如测试域 → 生产域：

1. 宝塔站点绑定新域名 + 证书  
2. 按第 3 节把 `{OLD}` 整站替换为 `{NEW}`  
3. 清缓存；微信/支付等回调 URL 若写死旧域，需在第三方平台同步改  

### 4.4 不需要动的情况

- 图片本身已是**相对路径**（如 `/uploads/...`），且 `site_url` 已正确 → 只需保证 `site_url` 对  
- 使用云存储且库里已是云存储完整域名 → 不要误替换对象存储域名；只替换站点自身域名相关字段  

---

## 5. 后台也可改，但覆盖范围不同

路径：**设置 → 系统设置 → 网站域名（site_url）**

| 方式 | 能改什么 | 改不了什么 |
|------|----------|------------|
| 后台改 `site_url` | 后续相对路径拼接前缀 | 已写入 DIY/主题/商品的绝对 URL |
| SQL `REPLACE` | 历史绝对 URL 批量修正 | — |

上线或换域：**后台改 `site_url` + 必要时 SQL 批量 REPLACE** 一起做。
