# 消息队列 / 定时任务 / 长连接 — 开启与使用说明

> 日期：2026-10-24  
> 场景：后台登录后出现「消息队列 / 定时任务 / 长连接」未开启提示  
> 适用：本仓库本地 Docker（`docs/docker`）与线上宝塔部署

官方说明亦可参考：[CRMEB 开启方法](https://doc.crmeb.com/single/v54/13667)。本文按**本项目实际命令、端口与本地架构**整理。

---

## 1. 三条提示分别意味着什么

| 提示 | 作用 | 未开会导致什么 | 检测方式（后台） |
|------|------|----------------|------------------|
| **消息队列** | 异步任务（短信、模板消息、部分商品/售后后置逻辑等） | 异步任务卡住或变同步/不执行 | 登录页派发 `CheckQueueJob`，成功则写入 `crmeb/runtime/.queue` |
| **定时任务** | 自动收货、未支付取消、自动好评、拼团到期退款、库存预警等 | 上述周期任务不跑 | `crmeb/runtime/.timer` 时间戳需在约 70 秒内被刷新 |
| **长连接** | 默认客服聊天、后台新订单弹窗通知等 | 客服/订单实时通知不可用 | 浏览器连 `ws(s)://域名/notice`（WebSocket）失败则提示 |

命令均在 **`crmeb/` 目录**（ThinkPHP 根，含 `think` 文件）执行，不是 `crmeb/public/`。

相关配置：

| 项 | 位置 |
|----|------|
| 队列驱动 | `crmeb/config/queue.php`（默认 `redis`） |
| 是否真正走队列 | 后台配置 `queue_open` **且** `.env` 中 `[CACHE] DRIVER = redis`（见 `QueueTrait`） |
| Workerman 端口 | `crmeb/config/workerman.php`：admin **40001**、chat **40002**、channel **40003** |
| WS 对外路径 | `getWorkerManUrl()` → `ws://域名/notice`、`ws://域名/msg`（需 Nginx 反代到 40001/40002） |
| Windows 一键脚本 | `crmeb/workerman.bat`（本机装 PHP 时用；Docker Linux 容器不用 bat） |

## 2. 本地 Docker 怎么开

本地当前是 `cjx-php`（`php -S :8089`）+ `cjx-mysql`。三条能力依赖不同前置，**按需开启**即可；纯改页面/接口时可不启，关掉提示也不影响大部分业务开发。

### 2.1 前置：Redis（开「消息队列」时必做）

真正启用消息队列需要：

1. 跑着 Redis  
2. `.env` 缓存驱动为 redis  
3. 后台打开「消息队列」开关（`queue_open = 1`）  
4. 常驻进程 `php think queue:listen --queue`

可在 `docs/docker/docker-compose.yml` 增加 Redis 服务（示例）：

```yaml
  redis:
    image: redis:7-alpine
    container_name: cjx-redis
    restart: unless-stopped
    ports:
      - "63791:6379"
    networks:
      - cjx_net
```

并给 `php` 服务补环境变量 / 写 `.env`：

```ini
[CACHE]
DRIVER = redis

[REDIS]
REDIS_HOSTNAME = redis
PORT = 6379
REDIS_PASSWORD =
SELECT = 0
```

然后：

```powershell
docker compose -f docs/docker/docker-compose.yml up -d
```

后台：**设置 → 系统设置**（或「消息队列」相关项）将队列开关打开。  
也可用 SQL（改完清缓存）：

```sql
UPDATE eb_system_config SET value = '1' WHERE menu_name = 'queue_open';
```

```powershell
docker exec cjx-php sh -c "rm -rf /app/runtime/cache/*"
```

> 若 `queue_open = 0` 或不配 Redis：多数任务会在进程内同步执行，登录检测可能仍提示队列未开（取决于检测 Job 是否写入 `.queue`）。本地要消提示并验证异步，请按上面四步做齐。

### 2.2 启动三个常驻进程（容器内）

先发布 Workerman 端口（改 compose 后重建 php 服务），例如：

```yaml
# php.ports 增加
- "40001:40001"
- "40002:40002"
# 40003 仅容器内通讯，一般不必映射到宿主机
```

在仓库根目录执行：

```powershell
# 消息队列（需 Redis + queue_open=1）
docker exec -d cjx-php sh -c "cd /app && php think queue:listen --queue"

# 定时任务（守护）
docker exec -d cjx-php sh -c "cd /app && php think timer start --d"

# 长连接（守护；Linux 容器可用 --d，一次拉起 admin/chat/channel）
docker exec -d cjx-php sh -c "cd /app && php think workerman start --d"
```

查看是否在跑：

```powershell
docker exec cjx-php sh -c "ps aux | grep -E 'queue:listen|timer|workerman' | grep -v grep"
docker exec cjx-php ls -la /app/runtime/.timer /app/runtime/.queue /app/runtime/workerman.pid 2>$null
```

停止示例：

```powershell
docker exec cjx-php sh -c "cd /app && php think timer stop"
docker exec cjx-php sh -c "cd /app && php think workerman stop"
# 队列：杀掉 listen 进程即可
docker exec cjx-php sh -c "pkill -f 'queue:listen' || true"
```

容器重建 / `compose down` 后，上述 `docker exec -d` 进程会丢，需重新执行。

### 2.3 长连接：本地还差 Nginx 反代

前端连的是 **`ws://localhost:8089/notice`** 和 **`/msg`**，不是直接连 `40001`。  
`php -S` **不会**把 `/notice` 升级成 WebSocket，因此只起 Workerman 仍会提示「长连接未开启」。

本地要真正连通，任选其一：

**方案 A（推荐与线上一致）：前面加 Nginx**  
反代 HTTP 到 PHP，并把 `/notice`、`/msg` 转到 40001/40002（配置片段见第 3.3 节）。站点用 `http://localhost`（或自定端口）访问，不再直连 8089。

**方案 B：仅联调接口，不测客服/订单弹窗**  
可忽略长连接提示；不影响普通 CRUD、商品、订单接口联调。

**方案 C：宿主机已装 PHP 7.4**  
在 `crmeb` 目录双击或运行 `workerman.bat`（会起 chat/admin/timer/channel），仍需本机 Nginx 配 `/notice`、`/msg`。

### 2.4 本地注意事项

| 点 | 说明 |
|----|------|
| 工作目录 | 必须在 `/app`（挂载的 `crmeb`），不要在 `/app/public` 跑 `think` |
| Windows 宿主机 | Docker 里是 Linux，用 `php think xxx --d`；**不要**在容器里跑 `workerman.bat` |
| 端口占用 | 40001/40002 被占会导致 Workerman 起不来 |
| 数据卷 | `runtime/*.pid`、`.timer`、`.queue` 在挂载目录里，注意别误删整个 `runtime` |
| 队列名 | 命令用官方文档写法：`php think queue:listen --queue` |
| 提示仍在 | 队列：确认 Redis、`DRIVER=redis`、`queue_open=1`、listen 在跑；定时：确认 `.timer` 时间新；长连接：确认 Nginx 反代 + Workerman + 浏览器能连上 WS |

## 3. 线上宝塔怎么开

生产环境建议：**Redis + Supervisor（或宝塔 Supervisor 管理器）+ 计划任务 + Nginx 反代 + Workerman 守护**。

假设站点代码根为 `/www/wwwroot/你的站点/crmeb`（以宝塔实际路径为准，下文写作 `<crmeb>`），PHP 为 **7.4**，运行用户多为 `www`。

### 3.1 Redis 与 `.env`

1. 宝塔安装 Redis，记下端口（默认 6379）与密码。  
2. `crmeb/.env`：

```ini
[CACHE]
DRIVER = redis

[REDIS]
REDIS_HOSTNAME = 127.0.0.1
PORT = 6379
REDIS_PASSWORD = 你的密码
SELECT = 0
```

3. 后台打开消息队列开关（`queue_open = 1`），清缓存。

### 3.2 消息队列（Supervisor）

宝塔：**软件商店 → Supervisor管理器**（或系统 Supervisor），添加守护进程：

| 项 | 建议值 |
|----|--------|
| 名称 | `crmeb-queue` |
| 运行目录 | `<crmeb>` |
| 启动命令 | `php think queue:listen --queue` |
| 运行用户 | `www` |
| 进程数量 | 1～2（按负载） |
| 自动重启 | 是 |

手动等价命令：

```bash
cd <crmeb>
php think queue:listen --queue
```

确认：`runtime/.queue` 在登录检测后存在且内容更新；或 Supervisor 状态为 RUNNING。

### 3.3 定时任务

**推荐：Workerman 版 timer 常驻（与官方安装说明一致）**

用 Supervisor 再加一条：

| 项 | 建议值 |
|----|--------|
| 名称 | `crmeb-timer` |
| 运行目录 | `<crmeb>` |
| 启动命令 | `php think timer start --d` |
| 用户 | `www` |

或 SSH：

```bash
cd <crmeb>
php think timer start --d
php think timer stop    # 停止
php think timer restart --d
```

确认：`runtime/.timer` 约每分钟内有更新；后台「定时任务」相关配置已启用需要的项。

> 部分文档写 crontab 每分钟执行 `php think timer start`，用于保活。若已用 Supervisor 守护 `timer start --d`，一般不必再叠一层；不要重复拉起多个 timer 进程。

### 3.4 长连接（Workerman + Nginx）

**① 启动**

Supervisor：

| 项 | 建议值 |
|----|--------|
| 名称 | `crmeb-workerman` |
| 运行目录 | `<crmeb>` |
| 启动命令 | `php think workerman start --d` |
| 用户 | `www` |

```bash
cd <crmeb>
php think workerman start --d
php think workerman stop
php think workerman restart --d
```

确认监听：

```bash
ss -lntp | grep -E '40001|40002|40003'
# 或
netstat -lntp | grep -E '40001|40002|40003'
```

**② Nginx 反代（必配）**

在**网站配置**中增加（端口与 `config/workerman.php` 保持一致）：

```nginx
# 后台管理员消息通知 → admin 40001
location /notice {
    proxy_pass http://127.0.0.1:40001/;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header X-real-ip $remote_addr;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header Host $host;
}

# H5 / 客服聊天 → chat 40002
location /msg {
    proxy_pass http://127.0.0.1:40002/;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header X-real-ip $remote_addr;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header Host $host;
}
```

重载 Nginx。HTTPS 站点前端会使用 `wss://`，需证书有效；若 Workerman 自身开 WSS，还需在后台配置证书路径（本项目命令里默认 `wss_open = 0`，通常由 Nginx 终结 TLS 再反代到本机 ws 即可）。

**③ 验证**

浏览器开发者工具 → Network → WS，登录后台后应能连上 `wss://你的域名/notice`（或 ws）。失败则仍会弹出长连接提示。

### 3.5 宝塔注意事项

| 点 | 说明 |
|----|------|
| 用户权限 | Supervisor 用户与站点 PHP 用户一致（常为 `www`），保证能写 `runtime` |
| 防火墙 | 40001/40002 **不必对公网开放**（经 Nginx 反代即可）；勿把 channel 40003 暴露公网 |
| 平滑发布 | 发版后必要时 `queue:restart`、重启 timer/workerman，避免旧代码常驻 |
| 多站点 | 同机多套 CRMEB 需改 `workerman.php` 端口，避免冲突 |
| 队列开关 | 只起 `queue:listen` 但 `queue_open=0` 或缓存不是 redis：业务仍可能不走 Redis 队列 |
| SELinux/权限 | `runtime` 不可写时 `.timer`/`.queue`/pid 失败，检测一直失败 |

## 4. 使用与联调建议

| 需求 | 最少要开 |
|------|----------|
| 只改后台页面 / 普通接口 | 可不启三者（忽略提示） |
| 测自动取消订单、自动收货等 | **定时任务** |
| 测异步短信/模板消息/队列 Job | **Redis + 队列开关 + queue:listen** |
| 测客服、后台新订单声音/弹窗 | **Workerman + Nginx `/notice` `/msg`** |

命令速查：

```bash
cd <crmeb>
php think queue:listen --queue
php think timer start --d
php think workerman start --d
```

Windows 本机 PHP（非 Docker）：

```bat
cd crmeb
workerman.bat
```

（bat 会起 chat、admin、timer、channel；队列仍需另开 `php think queue:listen --queue`，并自备 Redis。）

## 6. 排障清单

1. **队列一直提示**  
   `queue_open`？`CACHE DRIVER=redis`？Redis 通不通？`queue:listen` 是否在跑？登录后再看 `runtime/.queue`。

2. **定时一直提示**  
   `timer start` 是否存活？看 `runtime/.timer` 是否接近当前时间；是否有多个 timer 抢 pid。

3. **长连接一直提示**  
   Workerman 是否监听 40001？Nginx `/notice` 是否反代成功？浏览器 WS 是否被混合内容/证书/防火墙拦截？本地是否还在用裸 `php -S:8089`（无反代则必失败）。

4. **改完配置无效**  
   清 `runtime/cache`；Supervisor 里重启对应程序；确认改的是正在运行的那份 `crmeb` 代码目录。
