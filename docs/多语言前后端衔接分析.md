# CRMEB 项目多语言切换与内容显示分析

> 说明：用户提到的 `crmeb/app/adminapi/controller/PublicController.php` 主要为下载、扫码上传、系统信息等公共能力，**不包含多语言切换逻辑**。本文档按仓库实际代码梳理「商城端（uni-app）」与「管理后台（Vue）」两套前端，以及 PHP 后端的衔接方式。

---

## 一、总体架构（两套并行体系）

| 体系 | 用途 | 主要载体 |
|------|------|-----------|
| **A. CRMEB 数据库多语言** | 接口返回的 `msg` 文案翻译、站内消息等；uni-app 从接口拉取整包文案给 `vue-i18n` | 表 `lang_type`、`lang_country`、`lang_code`；函数 `getLang()`；请求头 **`Cb-lang`** |
| **B. ThinkPHP 语言包** | 框架级 `LoadLangPack` + `config/lang.php` 中的 `extend_list`（如 `app/lang/zh_cn.php`） | Cookie `cb_lang`、URL `lang`、Header `think-lang` 等（见框架默认与项目配置合并结果） |
| **C. 管理后台前端 i18n** | 后台界面文案（与商城数据库包独立） | `template/admin/src/i18n/**` 静态 JS + Element UI 语言包 |

实际业务接口里大量 `app('json')->success/fail('中文提示')` 走的是 **体系 A**：在输出 JSON 前经 `getLang()` 按当前语言转成对应译文。

---

## 二、链路梳理：前端 → 接口 → 后端 → 返回

### 2.1 商城端（template/uni-app，H5 / 小程序 / App）

#### 前端

1. **初始化语言与文案包**（`template/uni-app/App.vue`）  
   - 启动时调用 `getLangVersion()`（`GET .../api/lang_version`）。  
   - 若本地 `LANG_VERSION` 与接口不一致，则调用 `getLangJson()`，将返回数据写入 `localeJson`，并用 `Cache.set('locale', Object.keys(res.data)[0])` 同步当前语言码；再通过 `this.$i18n.setLocaleMessage` 注入 `vue-i18n`。

2. **默认 locale**（`template/uni-app/utils/lang.js`）  
   - 小程序/App：无缓存时默认 `zh-CN`。  
   - H5：无缓存时用 `navigator.language`。  
   - `VueI18n` 的 `messages` 初始来自 `uni.getStorageSync('localeJson')`。

3. **用户手动切换语言**（`template/uni-app/pages/users/user_info/index.vue`）  
   - `bindPickerChange`：`Cache.set('locale', 所选 value)` → `getLangJson()` → `uni.setStorageSync('localeJson', res.data)` → `setLocaleMessage` + `this.$i18n.locale = 所选 value`。

4. **所有需登录或业务请求携带语言**（`template/uni-app/utils/request.js`）  
   - 若存在 `uni.getStorageSync('locale')`，则设置请求头 **`Cb-lang`**（注意首字母大写 C，HTTP 头名大小写不敏感，ThinkPHP 读取为 `cb-lang`）。

#### 接口

- `GET /api/get_lang_type_list` → `PublicController::getLangTypeList`：可选语言列表（后台启用且未删除的 `lang_type`）。  
- `GET /api/get_lang_json` → `PublicController::getLangJson`：当前语言下的键值文案（供前端 `vue-i18n`）。  
- `GET /api/lang_version` → `PublicController::getLangVersion`：语言包版本，用于前端判断是否需要重新拉包。  
- 其它业务接口：同域名下 `uni.request`，自动带上 **`Cb-lang`**。

#### 后端

- **`getLangJson`**（`crmeb/app/api/controller/v1/PublicController.php`）  
  - 语言码 `range` 优先级：**请求头 `cb-lang`** → 后台默认语言（`lang_type.is_default=1` 的 `file_name`）→ `Accept-Language` 首段 → 兜底 `zh-CN`。  
  - 用 `lang_country` 按 `code` 匹配得到 `type_id`（匹配不到则 `type_id = 1`）。  
  - 从 `lang_code` 取 **`is_admin = 0`** 的「页面语言」条目，组装 `code => lang_explain`，缓存键如 `api_lang_*`。  
  - 返回：`{ "zh-CN": { ...键值对 } }` 形式（外层 key 为当前 `range`）。

- **`getLang()`**（`crmeb/app/common.php`）  
  - 与上相同的 **`cb-lang` → 默认 → Accept-Language → zh-CN** 优先级。  
  - 用 **中文表 `type_id=1`** 的 `remarks => code` 映射，把控制器里写的「中文标识」转成 `code`，再在**当前语言 type** 的 `lang_code` 中取 `lang_explain`。  
  - 支持占位符 `{:变量名}` 与 `$replace` 替换。

- **JSON 统一出口**（`crmeb/crmeb/utils/Json.php`）  
  - `make()` 内对 `msg` 执行 **`getLang($res['msg'], $replace)`**，因此接口返回的 `msg` 会随 `Cb-lang` 变化。

#### 返回

- 标准结构仍为 `{ status, msg, data }`；其中 **`msg` 已为翻译后字符串**（找不到翻译则保持原中文）。  
- `get_lang_json` 的 `data` 为对象：语言码 → 整包前端文案。

---

### 2.2 管理后台（template/admin）

#### 前端

- **纯前端切换**（`template/admin/src/layout/navBars/breadcrumb/user.vue` 的 `onLanguageChange`）  
  - 写入 `themeConfigPrev` 中的 `globalI18n`，并 `this.$i18n.locale = lang`。  
  - 可选值在 `initI18n` 中与 **`zh-cn` / `en` / `zh-tw`** 对应（与 `template/admin/src/i18n/index.js` 中 `messages` 的 key 一致）。

- **语言包来源**  
  - `template/admin/src/i18n/lang/*.js`、`i18n/pages/**/*.js` 及 Element UI 的 `zh-CN`、`en`、`zh-TW` 合并，**不经过 `get_lang_json` 接口**。

#### 接口

- 全局 Axios（`template/admin/src/libs/request.js`）中 **未发现** 向后台发送 **`Cb-lang`** 头。

#### 后端

- 管理端接口同样走 `app('json')`，故 **`msg` 仍会经 `getLang()`**。  
- 因无 `Cb-lang`，`getLang()` 使用 **缓存的默认语言名** `range_name`（来自 `lang_type.is_default=1`），或 Accept-Language，或 `zh-CN`。  
- 即：**后台界面语言（Vue i18n）与接口 `msg` 语言可以不一致**；接口 `msg` 跟随后台在「多语言」菜单里配置的默认语种及 `lang_code` 数据。

#### 返回

- 与商城相同：`msg` 经数据库多语言转换（体系 A）。

## 三、关键衔接细节小结

| 环节 | 要点 |
|------|------|
| 前后端约定头 | 商城 uni-app 使用 **`Cb-lang`**（代码里写法），服务端用 `$request->header('cb-lang')` 读取（HTTP 规范不区分大小写）。 |
| 中文作为 key 的来源 | 控制器/服务里 `fail('用户名不能为空')` 这类字符串，在中文语言类型（`type_id=1`）的 `lang_code` 里通过 **`remarks` 与 `code` 映射**；其它语言类型维护同一 `code` 的不同 `lang_explain`。 |
| 前端页面文案（商城） | 依赖 `get_lang_json` 拉取的 **`is_admin=0`** 词条 + `vue-i18n`；与接口 `msg` 使用同一套 `lang_code` 表，但 `getLangJson` 过滤了 `is_admin`，`getLang()` 未按 `is_admin` 过滤（按 `type_id` 拉全量 code 翻译）。 |
| 版本刷新 | `lang_version` 变化触发重新拉 `get_lang_json`，避免长期缓存旧文案。 |
| ThinkPHP `LoadLangPack` | `crmeb/app/middleware.php` 中注册了两次 `LoadLangPack`（重复注册为项目现状），与 **`getLang()` 数据库方案并行**；`config/lang.php` 中 `allow_lang_list` 为 `zh-cn`、`en-us`，扩展 `app/lang/zh_cn.php`、`en_us.php`。 |

## 四、后端「多语言转换」配置在哪里做？

1. **后台菜单路由**（`crmeb/app/adminapi/route/setting.php`）  
   - `lang_type`：语言类型（含是否默认、文件名 `file_name` 等）。  
   - `lang_country`：地区/语言码与 `type_id` 绑定（如 `zh-CN` → 某 `type_id`）。  
   - `lang_code`：具体翻译条目（`code`、`remarks`、`lang_explain`、`type_id`、**`is_admin`（0 页面 / 1 接口）** 等）。  
   - 可选：`lang_code/translate` 机器翻译（`LangCodeServices` 与 `Translate` 等）。

2. **代码侧兜底**  
   - `getLang()` 找不到映射或译文时 **原样返回传入字符串**（一般为中文）。  

3. **缓存**  
   - `getLang()`、`getLangJson` 等对映射与词表使用 `CacheService::remember`（如 3600 秒），改库后需依赖版本接口或清缓存策略更新。

## 五、目前「支持哪些语言」？

需分场景说明：

1. **商城 uni-app + 接口 `msg`（数据库）**  
   - **以数据库 `lang_type`（`status=1` 且未删除）为准**，常见安装包为 **简体中文（zh-CN）**、**英文（en-US）** 等，具体条目在 **`lang_country.code`** 与 **`lang_type.file_name`**。  
   - 列表接口：`get_lang_type_list` 返回当前启用类型。

2. **管理后台界面（静态）**  
   - 代码写死三套：**`zh-cn`、`en`、`zh-tw`**（见 `template/admin/src/i18n/index.js` 与 `user.vue`）。

3. **ThinkPHP 文件语言包**  
   - `crmeb/config/lang.php` 中 **`allow_lang_list`**：`zh-cn`、`en-us`；**`extend_list`** 指向 `app/lang/zh_cn.php`、`app/lang/en_us.php`。

## 六、若希望新增一种语言，需要做什么？

### 6.1 商城与接口 `msg`（数据库体系，必做）

1. 在后台 **语言类型** 中新增一种类型，配置 **`file_name`**（与现有命名风格一致，如 `ja-JP`）。  
2. 在 **语言国家/地区** 中新增 **`code`**（须与前端 `locale`、请求头 **`Cb-lang`** 一致，如 `ja-JP`），并绑定到该 `type_id`。  
3. 在 **语言列表 / lang_code** 中为该 `type_id` 维护与中文基准（`type_id=1`）相同 **`code`** 的各条 **`lang_explain`**；需要出现在 uni-app 整包里的条目 **`is_admin=0`**。  
4. 若需作为系统默认语种，在 **语言类型** 中将某一类型设为 **`is_default=1`**（并注意唯一性习惯）。  
5. 更新或触发 **`lang_version`**，使客户端执行 `getLangJson()` 重新拉包。  
6. 清理相关 Redis/文件缓存（若运维未自动失效），避免 `getLang()` 仍用旧缓存。

### 6.2 管理后台界面（若也要新语言）

1. 在 `template/admin/src/i18n/lang/`、`i18n/pages/` 下新增对应语言的 JS 文件。  
2. 修改 `template/admin/src/i18n/index.js` 的 `messages` 与默认 `locale`。  
3. 在 `user.vue` 的 `onLanguageChange` / `initI18n` 中增加新选项与分支。  
4. （可选）若希望 **管理端接口 `msg`** 也跟新语言走：需让浏览器请求带上 **`cb-lang`** 或与默认语言配置一致，否则仍按默认 `type_id` 翻译。

### 6.3 ThinkPHP 文件包（仅在使用 `__()` / 语言文件路径时扩展）

1. 在 `crmeb/config/lang.php` 的 **`allow_lang_list`** 中加入新语言标识。  
2. **`extend_list`** 增加新语言到新的 `app/lang/*.php` 文件。  
3. 按需维护 **`accept_language`** 映射。
